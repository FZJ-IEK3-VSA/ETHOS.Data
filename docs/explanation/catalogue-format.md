# The catalogue format

The catalogue is a directory of JSON, generated from hand-written YAML. This
page is about the choices behind it: why Frictionless, why loading is lazy, and
what sharding buys.

## Frictionless Data Packages

Each dataset is described by a
[Data Package](https://datapackage.org/) descriptor — `datapackage.json` — with
a `resources` array of files carrying `path`, `bytes`, `hash`, `mediatype`,
plus `sources` and `licenses` at the top.

Using an existing standard rather than inventing one buys three things: the
vocabulary for provenance and licensing already exists and is thought through;
the `"sha256:…"` hash convention Frictionless writes is the same `"alg:hash"`
convention [pooch](https://www.fatiando.org/pooch/) reads, so manifest values
pass straight through to the downloader untouched; and anybody who has met a
Data Package before can read one of these without documentation.

Institute-specific additions live under an `ethos:` prefix, which is exactly what
the standard's extension mechanism is for. They are listed in
[File formats](../reference/schemas.md).

## Two catalogues, one format

| | `ethos-data-catalog-internal` | `ETHOS.Data-Catalogue` |
|---|---|---|
| Role | `source` | `published` |
| Holds | `catalog.yaml`, `datasets/*/dataset.yaml`, `source_dir`, embargoed datasets | the generated public subset |
| Edited | by hand | never — regenerated by `ethos-data catalog publish` |

They share a `name`: the public one is a *subset view* of the same catalogue,
not a different catalogue. What distinguishes them is `ethos:catalog_role`, which
is written into the descriptor rather than inferred.

That key exists because inference was wrong in a way that mattered. The old
guess — index present, `catalog.yaml` absent — happened to be right, but it
could not tell a published catalogue from a source checkout somebody had
half-deleted, and it had nothing to say about a directory that was neither.
Standing in the wrong one now gets a straight answer: *this is a published
catalogue, it has no `dataset.yaml` and no `source_dir`, work in the source one
and republish* — with the path to the source catalogue next to it.

## Writer and reader ship together

`ethos_data.maintain` writes the descriptors that `ethos_data.catalog` reads, and
both live in this one distribution. That is deliberate.

The `ethos:` extensions are a format. A format whose writer and reader sit in
different repositories drifts silently: the reader grows a feature, the writer
never emits it, and nothing fails loudly enough for anyone to notice. Keeping
them together makes such a change a single commit that either works or does not.

Consumers never import `maintain` — `ethos_data` itself stays a read-only
library.

## Loading is lazy

`load_catalog` reads only `datacatalog.json`, the small index. A dataset's
`datapackage.json` is fetched the first time something actually asks for its
files.

This is not a micro-optimisation. The ERA5 inventory alone is ~64 MB and 170,000
resources; without laziness, every `ethos-data` invocation would download and
parse it just to answer a question about a different dataset.

So the index carries everything that can be answered without an inventory:

| Index key | Answers |
|---|---|
| `ethos:total_bytes`, `ethos:file_count` | how big is it |
| `ethos:access` | which root does it come from |
| `ethos:visibility` | is it published |
| `ethos:remote_prefix` | where are its bytes |
| `ethos:license_status` | should this warn |

`ethos-data list` and every access check are therefore free. Note in particular
that the **access class is read from the index, not the descriptor**: deciding
*where* a dataset comes from must never be the thing that pulls its file
inventory in.

## Sharding

A large dataset may go further. Its `datapackage.json` carries an `ethos:shards`
index instead of a `resources` array, and the inventory is split across
`manifests/<prefix>.json` files, one per directory prefix of
`ethos:shard_depth` segments:

```
datasets/era5/
|-- datapackage.json          # shard index only, no resources
`-- manifests/
    |-- _root.json
    |-- 4/6/5.json            # shard_depth: 3
    `-- 4/6/6.json
```

Selecting `4/6/5/**` then parses the 664 resources of that one tile rather than
all 170,000. Sharding is transparent: ask for `.resources` and every shard is
pulled in, exactly as before.

### Why keyed on the directory prefix

Because a shard must be *self-sufficient* for the things that travel together. A
shapefile's `.shp`, `.dbf` and `.shx` live in one directory and therefore land
in one shard, so resolving a sidecar never triggers a second fetch. The same
holds for a tile's variables.

### The shard filter is conservative on purpose

`_shard_could_match` decides which shards a pattern *could* reach. It may say
yes for a shard that turns out to hold nothing matching — the caller globs
properly afterwards, so the cost is one wasted fetch. It must never say no for a
shard that does, because that would silently drop files from a collection.

An extra fetch is a slow command. A dropped file is a wrong result.

Two cases the general rule cannot express, handled explicitly:

- The **root shard** holds files with no directory component at all, so only a
  single-segment pattern — or one starting with `**`, which absorbs zero
  segments — can name one. Without the distinction, every selection would drag
  the root shard in.
- A pattern that **runs out exactly at a shard's prefix** is one segment too
  short to match any file in it, since files sit *below* the prefix directory.

## Catalogue caching

A descriptor fetched from a version-pinned URL is written to disk and reused
forever — its contents cannot change, so there is nothing to invalidate. Writes
go through a temporary file and a rename, because two processes racing must
never see a half-written file.

A URL naming `main`, `master`, `HEAD`, `latest`, `dev` or `develop` is
recognised as moving and is never cached; development against the internal
catalogue would otherwise silently go stale. `ETHOS_CATALOG_NO_CACHE=1` disables
caching entirely.

Requests ask for gzip explicitly. These files compress about 40-fold, and
without the header `urllib` sends `Accept-Encoding: identity`.
