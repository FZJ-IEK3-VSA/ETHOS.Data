% Deployment view (C4): where ETHOS.Data runs and where its data lives.
%
% Three bands. Top: the machines outside the cluster (a package's CI runner,
% a workstation with its public cache and optional restricted caches,
% ETHOS.Data's own CI runner, an optional maintainer workstation). Middle: the
% hosts every band talks to (dCache, GitHub, Keycloak, JuGit). Bottom: the ICE-2
% cluster computer, with the users' environments on the left, the shared
% storage in the middle and the maintainer environment on the right, so users'
% reads come in from the left and maintainers' writes from the right without
% crossing. The shared storage puts project storage between the two kinds of
% cache, so both link into it without crossing an arrow.
%
% The hosts are ordered so that no arrow crosses another: dCache is under the
% users and the package CI, JuGit under the maintainers. The CI runner's
% arrow jogs left to the repository. The cluster's arrows to hosts further
% left run lower in the channel, so they nest; the users' download jogs left
% under them, past the cluster's label. Arrows into a host enter right of its
% label. Coordinates are millimetres; the picture is 162 wide.

  x=1mm, y=1mm,

  % white ring on the dark page; the core is the page ground instead.

  propnode/.style={depnode, dash pattern=on 3pt off 2pt},
  nlabel/.style={c4nodelabel},
  % A cylinder's caps grow with its width; these stores are wide, so their
  % caps are flattened to the height a narrow store has.
